## The platform facts this rests on

Live-probed read-only across four Mail backends (On My Mac, Exchange, Gmail IMAP, iCloud) at mailbox counts 0, 1, 2, 3, 11, 48. Byte-identical on every probe.

- `messages 1 thru 0` on a **non-empty** mailbox does **not** raise. It returns exactly **one** message, the first. Index `0` clamps to `1`, range normalizes ascending.
- `messages 1 thru -1` spans the **entire** mailbox. `thru -1` is end-relative.
- Out-of-range upper bound raises **-1719** (`Invalid index.`). No clamping.
- On an **empty** mailbox every slice form raises -1719, including `messages 1 thru 1`.
- `count of messages` can read **stale-high** (one mailbox reported 3, then 0 seconds later). Clamping to it is necessary but **not sufficient**; a slice still needs a `try`.
- **A plain AppleScript list is a different contract.** `items 1 thru 0 of {…}` raises **-1728**; `items 1 thru -1` returns the whole list; `items 1 thru -2` **silently drops the last item**. Do not carry the `messages` rule across to a collected list.

## Decisions

- **`delete_permanent` reuses `_search_message_ids` rather than a patched local script.** Safe under both candidate resolutions of the open founder decision, and deletes 55 lines instead of adding logic.
- **Non-positive bounds refuse; oversized bounds clamp with disclosure.** Clamping `0` up to `1` would act under a bound the caller set to "none" — the same defect relocated into Python. Oversized has an obvious intent, so it clamps, and the disclosure line appears in the dry-run preview too so preview and execute cannot appear to disagree.
- **`max_deletes` ceiling adopted `SCAN_BOUNDS["TRASH_SCAN"]`** (existed at 100, referenced nowhere). **`max_moves` ceiling tied to `MAX_WHOSE_IDS`** rather than a new constant, because 50 was already the enforced ceiling on both of that tool's paths.
- **`empty_trash` honoring `dry_run` is a deliberate behavior change.** Callers relying on the default now preview. The bundled skill documented exactly that call, so its docs changed in the same commit.
- **The commit-msg identity gate was cut, not deferred by choice.** It requires the validator from PR #90, which is not on `main`. A standalone copy of the leak-detection rules would be worse than no gate.
