## Goal

Give Cursor its own installed-plugin launcher contract instead of validating it
with Codex's relative-working-directory behavior.

## What shipped

- `plugin/mcp.json` launches
  `${CURSOR_PLUGIN_ROOT}/start_mcp.sh --draft-safe` and omits `cwd`.
- `tools/manifest_checks/cursor.py` independently enforces Cursor's launcher;
  Codex retains `./start_mcp.sh` with `cwd: "."`.
- Manifest regression tests reject Claude-root, relative, and explicit-`cwd`
  drift on the Cursor surface.
- All public release metadata and generated artifacts are synchronized at
  `3.11.6`.
- Maintainer documentation now distinguishes passed local Cursor Agent
  acceptance from still-separate Cursor marketplace/UI admission.

## Decisions

- Keep host-specific launchers explicit. Claude, Codex, and Cursor do not share
  one path-expansion contract even though they share one runtime payload.
- Treat local `--plugin-dir` acceptance as runtime proof only. It is not proof
  of Cursor Team Marketplace import, installation, update, or rollback.
- GitHub Actions remain intentionally unused; release blockers run locally in
  the coding session and git hooks.

## Remaining external gate

- Prove the corrected official-schema catalog through Cursor's current Team
  Marketplace/UI surface. The local `--plugin-dir` proof does not establish
  Marketplace import, installation, update, or rollback behavior.
