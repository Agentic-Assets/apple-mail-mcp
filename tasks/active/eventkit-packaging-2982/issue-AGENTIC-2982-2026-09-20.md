# AGENTIC-2982 — EventKit extra not shipped: research, findings, and fix plan

Date: 2026-09-20 · Issue: [AGENTIC-2982](https://linear.app/agenticassets/issue/AGENTIC-2982/apple-mail-mcp-eventkit-extra-is-not-shipped-so-the-calendar-fast-path) · Repo: `Agentic-Assets/apple-mail-mcp` @ `main` (`64ea2b8`) · Reporter evidence taken on plugin 3.12.2, macOS Darwin 25.6.0 arm64.

## 1. What the issue claims

Every installed copy reports `eventkit_available: {available: false, reason: "dependency_missing"}` because `requirements.lock` + `wheelhouse/` omit `pyobjc-framework-EventKit`. The EventKit engine code is complete; only the dependency is absent. Consequence: all calendar reads use the AppleScript engine with its 400-day recurring lookback, so a standing series created >400 days ago can be silently absent. Proof: manual `pip install` into the plugin venv flips the reason to a TCC label (`write_only`), so the dependency is the only packaging-side blocker; a second gate (TCC full access + `calendar-grant`) remains. Suggested scope: ship the dep, or document opt-in; improve `write_only`/`not_determined` guidance; consider a doctor/health check.

## 3. Design decision: ship EventKit by default in the offline payload

Considered (a) ship-by-default vs (b) stay opt-in with docs. **Ship by default**, because:

1. **Opt-in is structurally impossible for plugin installs.** The self-healing venv rebuilds from lock+wheelhouse; there is no second-lock/flag mechanism, and adding one (new lock files, new `start_mcp.sh` flag, builder/validator updates across 6+ files) is strictly more machinery than vendoring 3 wheels.
2. **Platform fit is exact.** The payload is already macOS-arm64 + CPython 3.13 only. PyPI `pyobjc-framework-EventKit` 12.2.2 is pure-Python (`py2.py3-none-any`, 7 KB) depending on `pyobjc-core>=12.2.2` + `pyobjc-framework-Cocoa>=12.2.2`, both shipping `cp313-macosx_10_13_universal2` binary wheels. `--only-binary` download + `--no-index` install both work; no compiler/Xcode needed. Total added payload ≈ 6.7 MB on 15 MB (~45% growth) — acceptable.
3. **Zero permission side effects.** Shipping the dep changes nothing at runtime until TCC full access is already granted: `eventkit_status()` never prompts, `get_engine()` `auto` mode keeps silent AppleScript fallback. Bundling cannot produce a new consent dialog.
4. **Linux CI stays green via marker.** A hard `pyproject.toml dependencies` entry would break Ubuntu CI (`pip install -e .` — pyobjc has no Linux wheels; `eventkit.py` docstring states pure-Python tests run on Ubuntu). Use a platform marker: `pyobjc-framework-EventKit>=10,<13; sys_platform == "darwin"`. `install_contracts.py` compares requirement *names* only, so the marker passes the `requirements.txt ⊆ pyproject deps` check.
